Problem → Approach → Result

The brief

Problem

One platform, three very different users

Customers needed to browse and check out securely. Merchants needed inventory and order tools. Admins needed oversight and approval control. Everything — schema, architecture, every integration — had to be designed from zero, working solo against a fixed deliverable timeline.

Approach

Layer it, then integrate

Started from the data model outward: entities and relationships first, then repositories, then a service layer carrying the business rules, then REST-style controllers per role. Payments, auth, and file storage were added as integrations against that stable core.

Result

A working, role-aware checkout flow

Three independent role workflows on one codebase, a Razorpay checkout that verifies payment server-side, OTP-gated login, and encrypted sensitive fields — packaged into a Docker image with a Maven build.

How it was built

Build sequence

1

Schema & entity design

Modeled products, orders, users, and roles in MySQL first, so every layer above it had a stable contract to build against.

2

Repository & service layer

Spring Data JPA repositories, with business logic kept in dedicated service classes, not in controllers.

3

Role-based controllers & views

Separate Spring MVC controllers and Thymeleaf templates for Customer, Merchant, and Admin, gated by role-based access control.

4

Razorpay checkout

Order creation → payment capture → server-side signature verification, so payment status is never trusted from the client alone.

5

OTP auth & AES encryption

Email OTP login via Spring Mail, with AES encryption applied to sensitive stored fields.

6

Containerize & automate

Dockerized the application and used Maven to automate the build.

What I'd do differently

Given more time, the next step would be splitting the sales dashboard queries into a read-optimized layer and adding integration tests around the Razorpay verification path — the part of the system where correctness matters most.
